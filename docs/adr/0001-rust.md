# ADR-0001: Implement maczap in Rust

* Status: accepted
* Date: 2026-11-14

## Context

maczap moves and deletes files on behalf of the user, sometimes as root. Its main
risk is a wrong **decision** (removing a path that does not belong to the target app),
not performance or memory. The tool needs a handful of macOS-native facts (code
signature Team ID and entitlements, running-application state) and many calls to
system tools without a public API (`launchctl`, `pkgutil`, `tccutil`, `osascript`).
It is distributed as open source through Homebrew and should be a single binary.

## Options

| Criterion | Python | Go | Swift | Rust |
|---|---|---|---|---|
| Native APIs | subprocess + text parsing | subprocess or cgo shims | direct | `objc2-*` crates (thin `unsafe`) |
| Selection TUI | Rich/questionary — excellent | huh/Bubble Tea — excellent | weak | ratatui — full control |
| Invariants in the type system | weak | medium (package-private constructors, no sum types) | good | strong (exhaustive enums, newtypes, ownership) |
| Development speed | highest | high | medium | lowest |
| Distribution | runtime needed; Homebrew formula painful | single binary | single binary | single binary |
| Open-source contributor pool for CLIs | large | large | small | medium |

## Decision

Rust (edition 2024, stable toolchain pinned in `rust-toolchain.toml`).

## Consequences

* The safety rules are enforced by the compiler: only the guard can construct
  `Verified<Candidate>`, and only that type is accepted by the quarantine; exhaustive
  `match` on `Confidence`, `TraceKind` and action kinds forces every new variant to be
  handled.
* Native code-signature and process APIs avoid parsing `codesign` output.
* Slower iteration and a steeper learning curve than Go or Python.
* Note: on the author's machine `/opt/homebrew/bin/swift` is OpenStack's
  `python-swiftclient`, not Apple Swift — irrelevant for Rust, recorded for posterity.
